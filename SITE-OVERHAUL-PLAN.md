## 1. Executive summary

This is a 7â€“9 day, single-engineer build in 8 phases. The public site gets a new design system, the sub-pages are regenerated from `tools/site/build.py`, and the hand-written homepage is rewritten in the same visual language. A hidden `/flow-hq/` admin panel sits on top of Supabase Auth + RLS. Public pages gain two deferred scripts: one for CMS overrides and one for cookie-less page-view tracking.

The provided spec is directionally correct but assumes a simpler repo than the one that exists. The three blocking issues are:

1. **`assets/site.css` is 40 KB and powers 40+ legacy class usages across the generated pages.** Replacing it with only the new CSS in the spec would leave every sub-page unstyled.
2. **The homepage is not generated by `build.py`.** It is a 29 KB hand-written `index.html` with its own copy of the Supabase lead form. Updating `build.py` alone does not touch it.
3. **`site_leads` is insert-only by design.** The admin panel's leads tab cannot read or update it without new authenticated RLS policies. The spec says "keep policies unchanged"; the plan keeps the existing ones and adds new ones.

Recommended resolution for all three: **additive compatibility layer, include `index.html`, add admin-only policies.** Details in Â§3 and Â§4.

## 5. Data model (additive SQL)

Keep everything currently in `supabase-schema.sql`. Add:

### 5.1 Tables

```sql
-- founder allowlist (no RLS policies: service role / SQL editor only)
create table if not exists public.admin_users (
  email text primary key,
  created_at timestamptz not null default now()
);
alter table public.admin_users enable row level security;

-- content overrides
create table if not exists public.site_content (
  id uuid primary key default gen_random_uuid(),
  page text not null,
  field_key text not null,
  field_value text not null,
  updated_at timestamptz not null default now(),
  unique (page, field_key)
);

-- visitor page views
create table if not exists public.site_visitors (
  id uuid primary key default gen_random_uuid(),
  page_url text not null,
  referrer text,
  user_agent text,
  screen_size text,
  timestamp timestamptz not null default now()
);

-- site-wide settings
create table if not exists public.site_settings (
  key text primary key,
  value text not null,
  updated_at timestamptz not null default now()
);
```

### 5.2 Admin check

```sql
create or replace function public.is_admin()
returns boolean
language sql
stable
security definer
set search_path = public
as $$
  select exists (
    select 1 from public.admin_users
    where lower(email) = lower(coalesce(auth.jwt() ->> 'email', ''))
  );
$$;

revoke all on function public.is_admin() from public;
grant execute on function public.is_admin() to authenticated;
```

Seed:

```sql

values ('theflowlabs01@gmail.com')
on conflict do nothing;
```

### 5.3 Policies

```sql
-- site_content: public read, admin write
alter table public.site_content enable row level security;
create policy "content public read" on public.site_content
  for select to anon, authenticated using (true);
create policy "content admin insert" on public.site_content
  for insert to authenticated with check (public.is_admin());
create policy "content admin update" on public.site_content
  for update to authenticated using (public.is_admin()) with check (public.is_admin());
create policy "content admin delete" on public.site_content
  for delete to authenticated using (public.is_admin());

-- site_settings: public read, admin write
alter table public.site_settings enable row level security;
create policy "settings public read" on public.site_settings
  for select to anon, authenticated using (true);
create policy "settings admin write" on public.site_settings
  for all to authenticated using (public.is_admin()) with check (public.is_admin());

-- site_visitors: admin read only. Inserts come from the service key in /api/track.
alter table public.site_visitors enable row level security;
create policy "visitors admin read" on public.site_visitors
  for select to authenticated using (public.is_admin());

-- site_leads: keep the existing anon INSERT policy; add admin read/update/delete
alter table public.site_leads add column if not exists notes text;
alter table public.site_leads add column if not exists updated_at timestamptz not null default now();

create policy "admins read leads" on public.site_leads
  for select to authenticated using (public.is_admin());
create policy "admins update leads" on public.site_leads
  for update to authenticated using (public.is_admin()) with check (public.is_admin());
create policy "admins delete leads" on public.site_leads
  for delete to authenticated using (public.is_admin());
```

**Deliberate deviations from the spec's SQL**

- `auth.role() = 'authenticated'` is replaced with `is_admin()`. Otherwise **any** user who signs up can edit content/settings.
- The spec's `site_visitors` insert policy `WITH CHECK (true)` would let anyone with the public anon key spam the table. Inserts happen only through the service key, which bypasses RLS, so no anon insert policy is created.
- `site_leads.status` already exists; the spec's `ADD COLUMN IF NOT EXISTS` is a harmless no-op.
- The spec's admin table columns "Email / Message" are actually `contact` / `idea` in this repo.

### 5.4 Indexes + stats RPC

```sql
create index if not exists idx_visitors_timestamp on public.site_visitors (timestamp desc);
create index if not exists idx_visitors_page on public.site_visitors (page_url);
create index if not exists idx_content_page on public.site_content (page);
create index if not exists idx_leads_created on public.site_leads (created_at desc);
```

## 7. API contracts

### `GET /api/content?page=home`

- Validate `page` with `^[a-z0-9-]{1,40}$`; reject otherwise.
- Query `site_content?page=eq.<page>&select=field_key,field_value`.
- Response: flat object `{ "hero-title": "...", ... }`, `{}` if none.
- `Cache-Control: public, s-maxage=60, stale-while-revalidate=300`.
- In-memory cache (60 s) plus edge cache.
- `?fresh=1` bypasses both, for admin preview only.
- Uses `SUPABASE_URL` + `SUPABASE_ANON_KEY` (fallback `SUPABASE_PUBLISHABLE_KEY`).

### `GET /api/settings`

- Returns `{ "accent_color": "#3B82F6", "section_home_team": "on", "seo_title_home": "...", ... }`.
- Same caching and key strategy as `/api/content`.
- This endpoint is an addition; the spec describes the settings behavior but no transport.

### `POST /api/track`

- Body `{ page, ref, w, h }`, max 1 KB.
- `page`: normalize to pathname, strip query, max 200 chars; ignore `/flow-hq`, `/api`, `/assets`.
- `ref`: store `new URL(ref).origin` only, max 120 chars.
- `user_agent`: header, max 500 chars; skip obvious bots (`/bot|crawler|spider|headless/i`).
- `screen_size`: `${w}x${h}` with numeric clamps.
- Rate limit: 1 request/IP/second using an in-memory `Map` with lazy eviction. Best-effort only; Vercel may run multiple instances.
- Insert with `SUPABASE_URL` + `SUPABASE_SERVICE_KEY` (`SUPABASE_SERVICE_ROLE_KEY` fallback), `Prefer: return=minimal`.
- `204 No Content` on success; `204` on malformed body too (fire-and-forget), `429` on rate limit.

### `GET /api/notify` (existing)

Do not touch. Keep `NOTIFY_TO`, not `NOTIFY_EMAIL` â€” the real code uses `NOTIFY_TO`. Document both in `.env.example` only if you want a compatibility alias.

## 16. Risks
